## 附录 A：方案选型记录

**本章解决**：记录早期需求分析的候选方案与取舍。

早期需求分析结论，已并入本规范。

### A.1 规范应满足的性质

_列：ID | 性质 | 说明。_

| 编号 | 性质 | 说明 |
|------|------|------|
| R1 | 精确 | 整数在任何路径上都不允许静默舍入 |
| R2 | 跨格式一致 | `toJson` 与 `toYaml` 得到语义相同的值 |
| R3 | 跨后端一致 | v2 与 sonic 输出逐字节一致 |
| R4 | 可区分 | `null` / 空集合 / 缺失 / 空字符串四者语义不同 |
| R5 | 可预测 | 失败必须显式（报错 + 退出码） |
| R6 | 可验证 | 每条规则可用一条命令复现 |

### A.2 数字候选方案

_列：方案 | 做法 | 优点 | 代价/风险 | 结论。_

| 方案 | 做法 | 优点 | 代价/风险 | 结论 |
|------|------|------|-----------|------|
| N0 维持现状 | 各路径各自处理 | 无改动 | 违反 R1/R2 | 拒绝 |
| **N1 精确整数类型** | 新增 `ExactInt`，JSON 裸数字、YAML `!!int`；解码与物化逐级构造 | 满足 R1/R2/R4 | 新增类型需五处识别 | **采纳（已实现）** |
| N2 超出 uint64 报错 | 解码期报错，声明整数上限 uint64 | 规则简单 | 拒绝合法 JSON | 备选（未采纳） |
| N3 一律 `big.Int` | 整数统一 `math/big.Int` | 语义最纯 | 无 `MarshalYAML`，改动面大 | 拒绝 |
| N4 一律 float64 | 整数走浮点 | 最简 | 2^53 以上静默损坏 | 拒绝 |

### A.3 空值候选方案

_列：方案 | 做法 | 优点 | 代价/风险 | 结论。_

| 方案 | 做法 | 优点 | 代价/风险 | 结论 |
|------|------|------|-----------|------|
| B0 typed nil → `null` | 保留自定义归一化 | 区分度最高 | 与库默认相反，面积大 | 后被推翻 |
| **库默认（typed nil → `{}`/`[]`）** | 减少自定义归一化，与 v2/yaml.v3 原生一致 | 面积最小 | sonic 需归一化（T1） | **采纳（V1，已实现）** |
| B1 输入期禁止 nil 集合 | 解码报错 | 消除歧义 | `null` 是常用配置值 | 拒绝 |

> 决策记录：数字采纳 N1；空值采纳**库默认**（推翻 B0）；`number` 不新增值类型；`uint` 不作为
> 类型名提供，非负约束交给 schema `minimum: 0`；由此登记 T1–T9，见 §13.2。
