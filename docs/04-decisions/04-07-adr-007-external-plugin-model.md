# ADR-007：外部插件模型（Proposed，仅记录，不实现）

## 1. 标题

ADR-007：外部扩展走**独立进程 + YAML 清单 + NDJSON 帧**；插件只扩展输入面与模板方言，不获得语义权

## 2. 状态

**Proposed**，2026-10-14。**本 ADR 只记录方向，不实现**：本阶段先做的是 L0 仓内接口统一重构
（`05-04` TASK-207），插件（L1–L3）分别对应 TASK-208/209/210，需另行授权。
协议草案与功能边界见 [`03-10`](../99-archive/03-design/03-10-external-plugin-protocol.md)。

## 3. 背景

- `REQ-SRC-06`（TOML）与 `REQ-SRC-07`（INI/.properties）都要求**新增核心依赖**；`REQ-SRC-11`（HTTP 值来源）
  要求核心具备网络能力。三者都在扩大核心的依赖面与能力面。
- `REQ-TPL-08`（模板函数注册，插件/WASM）与 `REQ-TPL-09`（切换模板引擎）已判 **⛔**，理由是
  Go `plugin` 需 cgo（破 K3 `CGO_ENABLED=0`）、WASM 需嵌入运行时（破 K3 低依赖），且 K2/K7 要求"受限引擎"。
- 但"⛔ 同进程加载第三方代码"不等于"⛔ 一切外部扩展"：**独立进程**不链接、不 cgo、不嵌运行时，
  可以把格式/来源/方言交给用户自己实现，而核心保持单静态二进制与确定性。

## 4. 决策

1. **形态**：插件是**独立可执行文件**，由核心用 `os/exec` 在**显式授权**下启动（无 shell、argv 数组），
   通过 **NDJSON 帧**交换数据；清单一律 **YAML**（复用现有 `yamlx`，零新依赖）。
2. **能力分层**：L0 仓内接口统一（重构，非插件）→ L1 输入面插件（格式/来源/子命令）→
   L2 引擎插件（1 次/模板）→ L3 formatter 常驻 sidecar（性能契约）。
3. **功能边界**：调用次数与**输入个数**同阶，绝不与**值数 × 管道步数**同阶；协议不提供
   `eval`/`format`/`render`/`tree`/`write` 帧，越界设计不可表达。
4. **语义权归核心**：合并、层序/`shadowed`、schema 物化、策略、退出码、写出、脱敏一律不外包。
5. **插件意义的判据**：只扩展**输入面 + 模板方言**；仅"换个地方实现同一语义"的扩展按接口重构处理，
   不称插件（见 `03-10` §1）。
6. **默认关闭**：不扫 `PATH`、不自动发现；`capabilities` 声明与开关必须一致（K1/K5）。

## 5. 备选与取舍

| 备选 | 结论 | 理由 |
|------|------|------|
| Go `plugin`（同进程） | ❌ | 需 cgo → 破 K3 `CGO_ENABLED=0`；ABI/工具链逐位耦合，实际不可分发 |
| WASM（同进程沙箱） | ❌ | 需嵌入运行时 → 破 K3 低依赖；与 `REQ-TPL-08` 的 ⛔ 同理 |
| 只做 L0 接口统一（不引入插件） | ⚠️ 可接受但意义有限 | 这是**重构**而非插件：用户拿不到新的表达力（本 ADR 的判断：值得先做，但不作为终点） |
| 每值 `fork+exec`（细粒度） | ❌ | 实测 0.6 ms/次（原生）、9 ms/次（解释器）→ 10 MiB 模板 60 s~15 min，直接击穿 `REF-04`/`test/perf` 门禁 |
| 每值常驻 sidecar（管道） | 🟡 有条件 | 实测 24 µs/次：常规模板可接受，10 MiB 场景 ≈2.4 s 吃掉门禁预算 → 默认关 + 性能契约 + 不进门禁 |
| **独立进程 + 清单 + 帧（选用）** | ✅ | 唯一同时满足 K1/K3/K5 与"可分发"的形态；引擎插件 1 次/模板，成本可控 |

## 6. 后果

- 正面：TOML/INI/HTTP 等可**仓外**实现，核心不引依赖、不触网；`REQ-SRC-06/07/11` 的实现压力从
  "核心加能力"变为"用户装插件"；扩展点显式、可审计（`--explain` 记录调用）。
- 代价：核心需维护一份协议与清单格式（版本兼容面）；纯插件形态下核心**无法强制**网络策略
  （超时/大小/重定向/SSRF 只能由插件自律），核心能强制的只有"是否 exec、进程超时、输出上限、
  无 shell、环境最小集、能力声明门禁"——**是防误用与可审计，不是沙箱**。
- 与既有结论的张力（**待产品侧拍板，本 ADR 不单方面改动**）：
  - `REQ-TPL-08`（模板函数注册 ⛔）：本 ADR 认为其 ⛔ 只针对**同进程**形态；子进程等价需求记为
    `REQ-TPL-10`（L2 引擎插件）与 L3（formatter sidecar）；
  - `REQ-TPL-09`（切换模板引擎 ⛔）：L2 允许用户用第三方引擎替换模板语义，与该条及 K7 措辞冲突，
    需要产品侧明确"内置引擎受限期约束 / 第三方引擎由用户显式启用并自担风险"这一修订是否成立。

## 7. 非目标

- 不实现插件安装器（下载/构建脚本属 K1/K5 危险能力，需单独评审）。`[FACT]`
- 不引入新的运行时依赖（不 cgo、不 WASM、不 shell）。`[FACT]`
- 不让插件参与值树的合并与策略决策。`[FACT]`
- 本 ADR 不含实现；`internal/` 代码不变。`[FACT]`
