# envsubst 升级版 PRD

## 1. 问题陈述

- **目标用户**：平台/DevOps 工程师 > CI 用户 > 容器镜像维护者。`[FACT]`（来源：需求提出者确认，2026-09-29）
- **使用场景**：在 CI/CD、K8s、NGINX、Systemd、容器 entrypoint 等场景中，从环境变量、`.env`、YAML/JSON values 渲染文本配置。
  `[INFERENCE]`（依据：线上证据与用户补充）
- **具体问题**：
    - 系统常无 envsubst，需要安装 gettext，Mac/Alpine/CI 尤为明显。`[FACT]`（来源：StackOverflow
      Q23620827、Q64112268；a8m/envsubst #64）
    - 缺少可靠转义，NGINX `$http_host`、`$1` 等会被误替换为空。`[FACT]`（来源：docker-library/docs #496；a8m/envsubst
      #13/#27/#38）
    - 默认值、数组、类型校验、多文件配置、安全 in-place 等能力缺失。`[FACT]`（来源：需求提出者补充与线上 issue）
- **证据**：GitHub `"envsubst" alternative` 搜索有 510 条结果；多个社区 issue 请求默认值、密钥注入、递归 `.env`、类型/约束与零依赖交付。
  `[FACT]`（来源：`docs/99-archive/00-raw/00-01-online-pain-points.md`）

## 3. 范围与非目标

### 本期 P0 范围

- 基础变量替换、默认值/存在性操作、转义、变量范围控制。
- schema 类型校验、数组/map、内联 `| type`（如果提供必须是 pipeline 第一个操作符，可缺省）。
- `.env`、YAML、JSON values 文件；多文件后者覆盖前者、数组替换、CLI `--set` 最高。
- Helm-like pipeline：`join` / `toJson` / `toYaml` / `quote` / `indent`。
- 安全 in-place、批量单文件、基础错误码。
- 单静态二进制与 amd64/arm64 多平台发布。

### P1 范围（待办，当前只实现 P0）

- include/partials、受限条件/循环、profiles/environments、dry-run/diff/check、容器镜像、conformance 测试、迁移文档。

### P2 范围（待办，当前只实现 P0）

- GNU/a8m/drone 兼容模式与 `migrate`/`convert` 自动转换。

### 非目标（Non-Goals）

- 不做 Helmfile/Helm/Kustomize 的发布编排替代品。`[FACT]`
- 不做图灵完备的通用编程语言或完整 Helm/Jinja 模板引擎。`[FACT]`
- 首版不做 GUI/Web 界面、远程配置中心、插件市场。`[FACT]`
- 默认不执行 shell 命令、不访问网络、不自动读取远程密钥。`[FACT]`

## 4. 用户故事与验收标准

### US-001 基础变量替换

作为 `平台/DevOps 工程师`，我希望 `用 $VAR / ${VAR} 渲染文本`，以便 `替换配置中的简单占位符`。`[INFERENCE]`

- Given 模板包含 `$PORT` 且值存在，When 执行渲染，Then 输出替换后的文本。
- Given 模板包含 `$1`，When 执行渲染，Then `$1` 按字面量输出，不替换为空。

### US-002 默认值与存在性操作

作为 `平台/DevOps 工程师`，我希望 `使用 :- / - / :+ / + / :? / ?`，以便 `处理未设置、空值和必填变量`。`[INFERENCE]`

- Given `${PORT:-8080}` 且 PORT 未设置或为空，When 渲染，Then 输出 `8080`。
- Given `${PORT:?必须设置}` 且 PORT 未设置，When 渲染，Then 报错并返回非零退出码。

### US-003 转义与范围控制

作为 `容器镜像维护者`，我希望 `用 $$ 输出字面量 $，并只替换指定变量`，以便 `避免误伤 NGINX/K8s 内置变量`。`[INFERENCE]`

- Given 模板包含 `$$` 和 `$http_host`，When 渲染，Then `$$` 输出 `$` 且 `$http_host` 保持不变。
- Given 使用变量白名单，When 渲染，Then 只替换白名单内变量。

### US-004 类型校验

作为 `平台/DevOps 工程师`，我希望 `渲染前按 schema 校验类型和约束`，以便 `避免错误配置进入运行时`。`[INFERENCE]`

- Given schema 声明 `port: integer` 且 minimum=1，When 输入 `PORT=8080`，Then 通过校验并渲染。
- Given 输入 `PORT=abc`，When 校验，Then 报错并指出变量、期望类型和来源。

### US-005 内联 `| type`

作为 `平台/DevOps 工程师`，我希望 `在模板中对少量变量快速声明类型`，以便 `不写完整 schema 也能做局部校验`。`[FACT]`
（来源：需求提出者确认）

- Given `${PORT | type int}`，When PORT=8080，Then 通过并输出原值。
- Given `| type` 出现在 formatter 后面，When 解析，Then 直接报错。

### US-006 数组/map 与 pipeline

作为 `平台/DevOps 工程师`，我希望 `用 join/toJson/toYaml/quote/indent 渲染数组和对象`，以便 `适配 YAML/JSON/文本配置`。
`[INFERENCE]`

- Given `${hosts | toJson}` 且 hosts 为数组，When 渲染，Then 输出 JSON 数组。
- Given `${app | toYaml | indent 2}`，When 渲染，Then 输出缩进后的 YAML。
- Given 输入不是字符串却直接使用 `indent`，When 渲染，Then 报错提示先转换类型。

### US-007 多文件 values 覆盖

作为 `平台/DevOps 工程师`，我希望 `按顺序加载多个 values 文件`，以便 `用后加载文件覆盖先加载文件`。`[FACT]`（来源：需求提出者确认）

- Given 基础文件和环境文件都声明 `app.port`，When 按顺序加载，Then 环境文件覆盖基础文件。
- Given 两个文件都声明数组，When 合并，Then 后加载数组整体替换前一个数组。
- Given CLI `--set` 和 values 文件冲突，Then CLI `--set` 优先。

### US-008 安全 in-place 与批量

作为 `CI 用户`，我希望 `安全原地写回和批量处理多文件`，以便 `避免 `< file > file` 截断并减少脚本拼接`。`[INFERENCE]`

- Given 对同一文件执行 in-place 渲染，When 成功，Then 临时文件原子替换，原文件不丢失。
- Given 某个输出文件无写权限，When 批量渲染，Then 失败并报告具体文件。

### US-009 dry-run / diff / check

作为 `CI 用户`，我希望 `预览变更、输出 diff 或检查是否需要更新`，以便 `接入流水线门禁`。`[INFERENCE]`

- Given 渲染结果与原文件一致，When 执行 `--check`，Then 退出码 0。
- Given 渲染结果会改变文件，When 执行 `--check`，Then 非零退出码并报告差异。

### US-010 include / 条件 / 循环（P1）

作为 `平台/DevOps 工程师`，我希望 `复用模板片段并按条件/数组生成内容`，以便 `处理复杂但仍受限的配置场景`。`[FACT]`
（来源：需求提出者确认 P1）

- Given 条件为真，When 渲染，Then 输出对应分支。
- Given include 嵌套超过 3 层，When 渲染，Then 报错。
- Given 对象循环，When 渲染，Then 按键排序输出，保证确定性。

## 5. 功能详述与交互逻辑

### Happy Path

1. 读取模板与值来源。
2. 合并 values 并应用 schema 默认值。
3. 执行类型解析、内联 `| type`、schema 约束校验。
4. 渲染模板并执行 formatter pipeline。
5. 输出到 stdout、文件或安全原地写回。

### Error Path

- 类型错误：指出变量、期望类型、实际值与来源。
- 未设置/空值：按 `--on-missing` / `--on-empty` 策略处理。
- 模板语法错误：指出模板文件与位置。
- schema 文件错误：指出 schema 路径与错误关键字。
- 批量渲染部分失败：报告失败文件，默认整体退出非零。

### 边界条件

- 最后一行无换行符时必须保留输出。
- `$1` 不替换。
- `$$` 转义。
- 大文件/大变量避免依赖 shell 参数长度。
- Windows CRLF / 路径 / 编码。
- 空数组、空对象、null、零值与 required。

## 6. 非功能需求

- **性能**：参考 GNU envsubst 基线，详见 `docs/reference/REF-04-gnu-envsubst-performance-baseline.md`。`[FACT]`
  （来源：需求提出者确认，2026-09-29）
    - 10MB / 200k 变量模板：耗时不超过 GNU envsubst 基线的 5 倍。`[ASSUMPTION]`
    - 峰值内存：不超过 GNU envsubst 基线的 5 倍。`[ASSUMPTION]`
    - 空输入启动：不超过 100 毫秒。`[ASSUMPTION]`
- **二进制优化**：采用常规二进制优化，静态编译、多架构发布。`[FACT]`（来源：需求提出者确认，2026-09-29）
- **安全**：默认不执行 shell、不访问网络、不自动读取远程密钥；`x-sensitive` 日志脱敏。`[FACT]`
- **数据埋点**：默认不上报用户配置内容；如需匿名统计，必须显式 opt-in。`[ASSUMPTION]` owner：产品负责人。
- **兼容性**：一期 extended 原生模式；P2 再提供 GNU/a8m/drone 兼容与转换。`[FACT]`
