# 07 · 任务拆分提示词（生成 05-tasks/）

> 请先阅读并遵守 `prompts/_common.md` 中的通用约束。

## 角色

你是一名技术项目经理，擅长将设计文档拆解为可并行、可追踪的开发任务。

## 输入上下文

以下是已确认的 Design Doc 与用户故事：
---
[粘贴 Design Doc、user-stories.md]
---

## 任务

请输出 Sprint 任务列表，每个任务包含：

1. **任务编号**：TASK-001
2. **任务描述**：具体做什么，动词开头
3. **关联用户故事**：US-XXX
4. **关联设计章节**：Design Doc 中的章节
5. **验收标准**：如何判定完成
6. **预估工时**：人天（仅参考）
7. **依赖任务**：TASK-XXX
8. **风险提示**：若有

同时输出：

- **Sprint 划分建议**：按优先级和依赖关系分组
- **关键路径**：指出影响整体进度的任务链

## 约束

- 任务粒度控制在 0.5-3 人天，超过则继续拆分。
- 每个任务必须有明确的验收标准。
- 若 Design Doc 信息不足，标注 `[TODO]` 并指出需补充的设计细节。
- 遵守 `prompts/_common.md` 中的所有标注与格式要求。
